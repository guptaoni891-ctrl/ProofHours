How it works

Four steps, each enforced by the contract rather than by this website.

  1. 01The university accredits an NGO

    Its admin registers the coordinator's wallet. Writes from any other wallet are refused.

  2. 02The NGO records hours

    Only a salted fingerprint of the student ID is stored, never a name or a real ID.

  3. 03Mistakes become new entries

    A correction or revocation is appended. The original stays visible, so nothing is quietly rewritten.

  4. 04Anyone can verify

    The verifier's browser recomputes the fingerprint and reads the full history directly from the chain.

What is public, and what is not

On the ledger

  • Accredited coordinator wallets and their names
  • Events and their maximum hours
  • Append-only records: hours, issuer, time, corrections
  • Salted fingerprints of student IDs

Never on the ledger

  • Student names or real IDs
  • The secret salts
  • Any other personal data

Contract rules

Each scenario asks the contract to do something it must refuse. The refusal comes from the contract itself, not from this website. Checks are read-only, so no wallet is needed.
